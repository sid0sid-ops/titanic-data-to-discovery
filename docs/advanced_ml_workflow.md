# Advanced ML Workflow

The advanced notebook section demonstrates the project as a complete machine learning workflow, not only a Titanic prediction example.

## Workflow

```text
Robust Data Loading
-> Missing Value Handling
-> Leakage-Safe Feature Engineering
-> Train/Test Split
-> Pipeline + ColumnTransformer
-> Logistic Regression / Random Forest
-> GridSearchCV
-> Accuracy + ROC-AUC + Confusion Matrix
-> Prediction Simulation
```

## Robust Data Loading

The advanced section uses a loader with fallback sources so a presentation is less likely to fail because one public URL is temporarily unavailable.

## Zero-Leakage Preprocessing

The custom group median age imputer is implemented as a Scikit-Learn transformer. It learns medians only during `fit`, which means it learns from the training fold rather than from the entire dataset.

## Pipeline and ColumnTransformer

The workflow uses Scikit-Learn `Pipeline` and `ColumnTransformer` so numeric and categorical preprocessing are reproducible and connected directly to the estimator.

## Model Comparison

Logistic Regression is the interpretable baseline. Random Forest is a non-linear comparison model. The advanced section uses `GridSearchCV` to compare model settings through stratified cross-validation.

An archived OpenML reference run reported:

```text
Test Accuracy: 0.8473 / 84.73%
```

**Metric provenance:** OpenML Titanic, 1,309 rows; Logistic Regression; numeric features `age`, `sibsp`, `parch`, `fare`, `family_size`; categorical features `pclass`, `sex`, `embarked`, `is_alone`, `title`, `has_cabin`; stratified 80/20 holdout; `random_state=42`; source `notebooks/02_Titanic_OpenML_Reference_Workflow.ipynb`. This historical result is retained for reference and is not the current Kaggle assignment baseline.

## ROC-AUC

ROC-AUC is included as an additional diagnostic because it evaluates ranking performance across decision thresholds. The ROC curve is generated by:

```bash
python3 scripts/generate_titanic_figures.py
```

## Leakage Warning

The columns `boat` and `body` are post-disaster fields. They are excluded because using them would leak the answer and make the model cheat.
